# Diagramming Rules

適用於以 Mermaid 表達既有系統或目標設計的結構、流程、狀態與資料關係。

## 定位

- Preset 代表任務類型；Diagram Profile 代表圖的種類，兩者不可混用。
- 只選擇能回答本次問題的 Profile，不因存在 Profile 就全部產圖。
- 圖表補充結構化理解，不取代 Findings、來源定位與待確認事項。

## 共用規則

### 切圖

- 一張圖只回答一個主要問題；架構、業務流程、呼叫順序、狀態與資料流分開表達。
- 跨越多個業務領域、生命週期或整合邊界，或節點超過約 15 個而難以閱讀時，依 Profile 的切割條件拆圖。
- 拆圖後保留必要的銜接節點與一致名稱，避免各圖無法對照。
- 優先使用短標籤；詳細欄位、條件與來源改放圖後說明。

### 可信度

- 圖表標明現況或目標；現況以程式碼、設定與 Schema 證實，目標以已確認需求或 Engine 設計為依據；目標不代表已實作。
- 引用既有分析與 Engine 產物，未確認目標標記 Pending / Assumption。
- 推測關係使用虛線並標記 `To Verify`；完全未知的關係不補線。
- 圖後列出主要來源檔案或符號；無法定位來源時明確標記。
- 不為了讓圖完整而虛構模組、狀態、資料表、呼叫或轉換。

### Token 節省

- 優先沿用已確認的 Findings 與呼叫鏈，不為畫圖重新掃描整個 Repository。
- 先決定本次 Profile 與範圍，再只讀取補齊必要節點和關係的檔案。
- 相同關係只在最適合的圖中表達，不跨圖重複展開。
- 預設先產最小可用圖；只有圖無法回答問題時才增加節點、分支或第二張圖。

## Diagram Profiles

### `module-map`

| 項目 | 規則 |
| --- | --- |
| 使用時機 | 說明系統邊界、主要模組、責任與高階相依性。 |
| 建議 Mermaid 類型 | `flowchart`。 |
| 內容範圍 | UI、API、Service、Data Access、Database、外部系統等實際元件與方向性相依。 |
| 切割條件 | 不同業務領域或外部整合各自成圖；跨層總覽只保留主要模組。 |
| 必要元素 | 系統邊界、模組名稱、主要責任、依賴方向、整合點。 |
| 排除內容 | 類別清單、方法細節、資料表欄位與逐步業務流程。 |
| 基本驗證 | 現況節點可定位到實際元件；目標節點可定位到已確認需求或設計，依賴方向與入口一致。 |

### `business-flow`

| 項目 | 規則 |
| --- | --- |
| 使用時機 | 說明使用者或業務事件如何經過判斷並產生結果。 |
| 建議 Mermaid 類型 | `flowchart`。 |
| 內容範圍 | 起點、主要步驟、業務判斷、例外分支與結束結果。 |
| 切割條件 | 不同角色、主要情境或可獨立說明的子流程分開。 |
| 必要元素 | 觸發事件、執行角色、判斷條件、成功結果、失敗或例外結果。 |
| 排除內容 | Controller、Service 等技術分層與不影響業務結果的內部呼叫。 |
| 基本驗證 | 每個判斷分支都有去向，流程結果符合已確認業務規則。 |

### `call-chain`

| 項目 | 規則 |
| --- | --- |
| 使用時機 | 追蹤一次操作、API、排程或事件的實際呼叫先後順序。 |
| 建議 Mermaid 類型 | `sequenceDiagram`；只需靜態相依時可用 `flowchart`。 |
| 內容範圍 | 入口、Controller、Service、Repository、SP／Table 與外部服務的必要鏈路。 |
| 切割條件 | 不同入口、同步／非同步路徑或獨立例外流程分開。 |
| 必要元素 | 呼叫者、被呼叫者、先後順序、關鍵輸入／輸出、錯誤或回傳位置。 |
| 排除內容 | 與入口無關的方法、完整類別成員與未影響結果的內部細節。 |
| 基本驗證 | 呼叫順序、方法或端點名稱及跨層參數可由實際來源對照。 |

### `state-transition`

| 項目 | 規則 |
| --- | --- |
| 使用時機 | 說明單一實體的狀態、觸發事件、條件與終止結果。 |
| 建議 Mermaid 類型 | `stateDiagram-v2`。 |
| 內容範圍 | 現況或已確認目標設計的狀態、轉移事件、Guard、成功、取消與例外狀態。 |
| 切割條件 | 不同實體或互相獨立的生命週期分開；子狀態過多時另畫子流程。 |
| 必要元素 | 初始狀態、狀態名稱、觸發事件、必要 Guard、終止或例外狀態。 |
| 排除內容 | UI 導航、方法呼叫順序與沒有已確認需求或設計依據的理想狀態。 |
| 基本驗證 | 每條轉移都有來源依據；不可達、重複或語意不明狀態標記待確認。 |

### `data-flow`

| 項目 | 規則 |
| --- | --- |
| 使用時機 | 說明資料從來源經轉換、儲存到消費端的流向。 |
| 建議 Mermaid 類型 | `flowchart`。 |
| 內容範圍 | 資料來源、關鍵轉換、Queue／API／SP、儲存位置、消費端與主要 Key。 |
| 切割條件 | 不同資料主題、獨立管線或外部系統邊界分開。 |
| 必要元素 | 來源、目的地、流向、讀／寫或轉換動作、持久化位置、對應 Key。 |
| 排除內容 | 不影響資料結果的方法呼叫、無關欄位與純 UI 操作步驟。 |
| 基本驗證 | 以一組代表性資料或 Key 由來源追到目的地，確認方向與轉換一致。 |

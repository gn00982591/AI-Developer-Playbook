# 專案進度與追蹤表規則

適用於所有專案的建立、接續與進度更新。

## 必要交付文件

- 每個專案都必須建立並持續維護對應的 Excel 進度追蹤表（`.xlsx`），並與專案 Markdown 文件（`.md`）配對交付。
- 優先沿用既有文件、檔名、路徑、工作表與欄位格式；已有追蹤表時直接更新，不重建另一份。缺少 Excel 時依已確認資料補建。
- 實際專案資料保存在該專案；中央 Playbook 只保存共用流程。

## 更新流程

1. 讀取現有專案 MD、Excel 與本次提供的進度來源，確認更新截止日期。
2. 整理截至當下的完整進度：保留已完成項目與完成紀錄，同時更新進行中、待處理、待解問題及下一步，不只追加本次完成事項。
3. 在同一次更新中同步修改 MD 與 Excel；項目識別、狀態、負責單位／人員、日期、問題及下一步須一致。既有格式不同時核對對應欄位，不強制重排。
4. 未提供或無法確認的資訊標記「待確認」，不得自行推定完成、進度百分比、負責人或日期；保留原有已確認紀錄。
5. 核對兩份文件的一致性與 Excel 可開啟性；修改既有工作簿時檢查公式、格式與工作表是否保留。
6. 交付更新後的 MD 與 Excel，說明更新截止日期、主要變化與待確認事項。任一文件未更新或無法驗證時，明列缺漏，不宣稱同步完成。

## 追蹤內容與完成條件

- 新建追蹤表至少涵蓋：項目識別、工作項目、狀態、負責單位／人員、預計完成日、實際完成日、最新進度／更新日期、待解問題與下一步。未知值標記待確認。
- 狀態至少能區分已完成、進行中與待處理；待解問題可用既有問題欄或工作表維護。
- MD 可保留摘要、Excel 保留逐項明細，但相同事項的狀態與日期不得矛盾；不另建一套取代既有 Spec Engine Tasks 的正式任務來源。
- 兩份文件均已更新至相同截止日期、已完成紀錄保留、未完成項目可續追且一致性核對通過，才算本次進度更新完成。

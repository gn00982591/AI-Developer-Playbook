# 專案進度與追蹤表規則

適用於所有專案的建立、接續與進度更新。

## 專案建立與資料歸類

使用者要求建立專案、專案控版或整理專案資料夾時，先確認專案性質、工作線、目前階段及已確認的結構，再執行交辦事項。使用者明確指定的新結構優先於既有位置。

- 範本依序採用本次明確指定、該子專案已確認的正式範本、上層明確指定且適用的共用範本。將正式範本的用途與可開啟路徑登記在專案入口。已指定的範本找不到時，回報路徑與缺口，先處理可確認的項目。沒有指定時，專案進度 Excel 使用 Playbook 內建的 [紅色抬頭追蹤表範本](../templates/project-progress.xlsx)，其他既有文件沿用原格式。
- 先判斷目標是多專案控管根目錄或個別專案。控管根目錄按個別專案分目錄，保留總覽與共用入口。個別專案內按已確認的階段及用途切分，工作線或版本放在對應階段下。開發階段示例供開發類工作參考。
- 已指定 `Include only support-related content.` 時，交付內容限於該支援案的問題、重現條件、影響、診斷、處理與驗證紀錄、待辦及相關附件。若需要切分目錄，按支援案已確認的流程及實際資料建立。

1. 將階段資料夾直接建立在專案根目錄。階段名稱及數量依專案流程決定。相同階段新增版本、工作線或資料類型時，在該階段內新增子資料夾；只有實際流程增加階段時，才在根目錄新增階段資料夾。
2. 根目錄保留 `AGENTS.md`、`README.md`、`.gitignore` 及一份全案 Excel 追蹤表。追蹤表沿用已確認的檔名，與根目錄 Markdown 入口配對維護。不同版本及工作線共用同一份追蹤表，保留已完成及已結案的紀錄與確認日期。
3. 盤點全案既有資料，涵蓋上一版、已結案版本及本次新增需求。先核對原位、新位與同名檔案，再按實際用途搬入對應階段，保留來源內容。跨階段共用內容只保存一份，由其他階段引用。
4. Playbook 保持獨立 Git repository，安裝路徑依專案入口登記。需要保存一次性產物時才建立 `.ai-output/`，正式文件歸入對應階段。一次性預覽與建置的 `node_modules`、快取及工作目錄使用系統暫存位置。
5. 搬移後更新文件連結、專案導航、匯入與套件載入、啟動路徑、測試及建置設定、預設輸出位置和控版忽略設定。核對檔案位置、必要內容一致性、連結與受影響的執行流程。無法搬移或驗證的項目記錄實際位置與原因；無法判定的分類或執行事項再確認，先處理其餘已確認項目。

### 本機產檔工具的配置示例

| 根目錄階段 | 歸檔內容示例 |
| --- | --- |
| `01_需求與可行性評估/` | 原始資料、郵件、需求分析、可行性評估及決策紀錄 |
| `02_格式與輸出設計/` | 資料映射、格式規格、版型及輸出設計 |
| `03_程式開發與建置/` | 來源碼、開發依賴、啟動程式、建置工具及開發暫存 |
| `04_測試與驗收/` | 測試程式、測試輸出、驗證摘要、問題回報及驗收證據 |
| `05_交付與結案/` | 正式交付包、使用說明、交付紀錄及結案摘要 |

例如第四階段可按需求新增 `原版驗收/` 與 `新版測試/`，並使用根目錄的 `專案進度.xlsx` 追蹤全案。導入與介接案則可依實際流程增設上線切換、上線支援與移交等階段，平台設定與介接開發可作為並行工作線。

## 必要交付文件

- 每個專案都必須建立並持續維護對應的 Excel 進度追蹤表（`.xlsx`），並與專案 Markdown 文件（`.md`）配對交付。
- 優先沿用既有文件、檔名與工作表；格式依更新流程第一步決定；已有追蹤表時直接更新，不重建另一份。缺少 Excel 時複製選用的工作簿範本到專案目錄，依已確認資料填寫。
- 實際專案資料保存在該專案；中央 Playbook 只保存共用流程。

## 更新流程

1. 讀取現有專案 MD、Excel 與本次提供的進度來源，確認更新截止日期。依「專案建立與資料歸類」選用範本。專案有指定範本時，在根目錄 `AGENTS.md` 登記可直接開啟的引用。更新前讀取選用的範本，比對欄位與順序、格式、凍結位置及允許的狀態值（含空白規則）。有差異時依選用的範本調整，保留既有資料與公式。
2. 整理截至當下的完整進度：保留已完成項目與完成紀錄，同時更新進行中、待處理、待解問題及下一步，不只追加本次完成事項。
3. 在同一次更新中同步修改 MD 與 Excel；項目識別、狀態、負責單位／人員、日期、問題及下一步須一致。欄位映射依第一步確認的格式處理。
4. 未提供或無法確認的資訊標記「待確認」，不得自行推定完成、進度百分比、負責人或日期；保留原有已確認紀錄。
5. 核對兩份文件的一致性與 Excel 可開啟性；修改既有工作簿時檢查資料、公式及工作表，並核對工作簿符合第一步確認的格式。指定範本或工作簿無法讀取時，列出未核對項目，待驗證後才可標記 Excel 更新完成。
6. 交付更新後的 MD 與 Excel，說明更新截止日期、主要變化與待確認事項。任一文件未更新或無法驗證時，明列缺漏，不宣稱同步完成。

## 追蹤內容與完成條件

- 新建追蹤表至少涵蓋：項目識別、工作項目、狀態、負責單位／人員、預計完成日、實際完成日、最新進度／更新日期、待解問題與下一步。未知值依範本規則處理，必要時於備註或 MD 標記待確認。
- 狀態值依指定範本填寫；未指定時至少能區分已完成、進行中與待處理；待解問題可用既有問題欄或工作表維護。
- MD 可保留摘要、Excel 保留逐項明細，但相同事項的狀態與日期不得矛盾；不另建一套取代既有 Spec Engine Tasks 的正式任務來源。
- 兩份文件均已更新至相同截止日期、已完成紀錄保留、未完成項目可續追且一致性核對通過，才算本次進度更新完成。

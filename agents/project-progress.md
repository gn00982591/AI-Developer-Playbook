# 專案進度與追蹤表規則

適用於所有專案的建立、接續與進度更新。

## 專案建立與資料歸類

使用者要求建立專案、專案控版或整理專案資料夾時，先依已提供的目標、範圍與現有文件判斷，再執行交辦事項。

1. 判定整體專案類型、各工作線與目前階段。若同一導入案包含平台設定及跨系統介接開發，將兩者納入同一專案的工作線，共用專案進度及驗收。
2. 優先沿用已確認的階段、目錄與追蹤位置。未定義階段時，按專案範圍選用適合的流程。導入與介接案可採用「啟動 → 需求與可行性評估 → 流程與介接設計 → 平台設定與程式開發 → 整合測試與使用者驗收 → 上線切換 → 上線支援與移交」，平台設定與介接開發可並行。
3. 已交辦建立或整理資料夾時，直接建立所需階段目錄，按用途將既有資料歸到對應階段及工作線，沿用指定的全案追蹤位置。更新專案入口及受影響的連結，並核對實際檔案位置。
4. 可從現有資料判定的事項直接處理。只有會影響分類或執行且無法判定的事項才詢問，並繼續處理其餘已確認的工作。無法搬移或核對的檔案，記錄實際位置與原因。

## 必要交付文件

- 每個專案都必須建立並持續維護對應的 Excel 進度追蹤表（`.xlsx`），並與專案 Markdown 文件（`.md`）配對交付。
- 優先沿用既有文件、檔名、路徑與工作表；格式依更新流程第一步決定；已有追蹤表時直接更新，不重建另一份。缺少 Excel 時依已確認資料補建。
- 實際專案資料保存在該專案；中央 Playbook 只保存共用流程。

## 更新流程

1. 讀取現有專案 MD、Excel 與本次提供的進度來源，確認更新截止日期。先查專案入口或文件是否指定追蹤表範本。專案有指定範本時，在專案規則中提供可直接開啟的引用，更新前讀取範本並比對欄位與順序、凍結位置及允許的狀態值（含空白規則）。有差異時以指定範本為準，保留既有資料與公式。專案未指定範本時沿用既有格式。
2. 整理截至當下的完整進度：保留已完成項目與完成紀錄，同時更新進行中、待處理、待解問題及下一步，不只追加本次完成事項。
3. 在同一次更新中同步修改 MD 與 Excel；項目識別、狀態、負責單位／人員、日期、問題及下一步須一致。欄位映射依第一步確認的格式處理。
4. 未提供或無法確認的資訊標記「待確認」，不得自行推定完成、進度百分比、負責人或日期；保留原有已確認紀錄。
5. 核對兩份文件的一致性與 Excel 可開啟性；修改既有工作簿時檢查資料、公式及工作表，並核對工作簿符合第一步確認的格式。指定範本或工作簿無法讀取時，列出未核對項目，待驗證後才可標記 Excel 更新完成。
6. 交付更新後的 MD 與 Excel，說明更新截止日期、主要變化與待確認事項。任一文件未更新或無法驗證時，明列缺漏，不宣稱同步完成。

## 追蹤內容與完成條件

- 新建追蹤表至少涵蓋：項目識別、工作項目、狀態、負責單位／人員、預計完成日、實際完成日、最新進度／更新日期、待解問題與下一步。未知值依範本規則處理，必要時於備註或 MD 標記待確認。
- 狀態值依指定範本填寫；未指定時至少能區分已完成、進行中與待處理；待解問題可用既有問題欄或工作表維護。
- MD 可保留摘要、Excel 保留逐項明細，但相同事項的狀態與日期不得矛盾；不另建一套取代既有 Spec Engine Tasks 的正式任務來源。
- 兩份文件均已更新至相同截止日期、已完成紀錄保留、未完成項目可續追且一致性核對通過，才算本次進度更新完成。

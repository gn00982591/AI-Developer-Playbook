# Testing Rules

適用於 Build、Test 與變更驗證。

## 規則

- 先執行與變更直接相關的最小驗證範圍。
- 必要時再擴大到完整 Build / Test。
- 不因小幅修改自動執行與需求無關的大型測試流程。
- 驗證失敗時，先確認是否與本次 Change 有直接關係。
- 回報實際執行的命令、成功/失敗結果與尚未驗證項目。
- 不把「未執行測試」描述成「測試通過」。

涉及資料存取時，另套用 [Data Access Rules](data-access.md)，沿用同版本已核對的索引與來源，只補讀本次直接相依內容。

## 驗收證據

- 依 Engine 或 Lightweight 方案的驗收驗證；按需核對需求、Tasks、實作與結果一致性。
- Engine 文件檢查、Build / Test 與資料驗證分開記錄，彼此不替代。
- 純文件或圖表變更驗證來源、引用及一致性，不強制無關 Build / Test。

# 程式註解與技術說明

讓維護者在閱讀程式時，能就近找到呼叫契約、規則原因及例外行為。

### 適用範圍

涵蓋專案自行維護的前端、後端、共用程式、測試及開發與發佈工具腳本。依專案實際使用的格式套用，例如 C#、TypeScript、JavaScript、Vue、CSS、Python 和 PowerShell。集中盤點時排除生成檔、第三方相依及建置產物。

### 加入既有開發流程

| 階段 | 檢查事項 |
| --- | --- |
| 實作前 | 從專案的 `AGENTS.md` 找到註解規範，依受影響的語言與格式選讀，沿用專案慣例。 |
| 實作中 | 檢查受影響的類別、型別、DTO、屬性、方法與前端元件契約。將規則原因及例外寫在生效處，並更新跨檔案流程的 README。 |
| 驗證時 | 對照宣告、呼叫端和實際執行路徑，核對前置條件、空值、回傳值及錯誤處理。若搬移規範，從 `AGENTS.md` 驗證索引及各頁相對連結。 |
| 審查時 | 依受影響的模組與功能群組檢查，例如 Vue Props／Emits／Slots、特殊 template 條件與 CSS 版型限制。確認註解位置與內容符合實作，移除失效說明。 |
| 交付時 | 記錄已檢視範圍、補寫位置、驗證結果與待檢視模組。純註解與文件變更依差異驗證。涉及程式行為或功能契約變更時，使用對應的測試與規格流程。 |

### 撰寫判斷

1. **確認受影響範圍。** 讀取 `AGENTS.md` 所指的規範，查看本次差異、相關呼叫端及技術文件，找出需要補寫或修正的說明。
2. **核對行為。** 沿實際呼叫路徑查核業務規則的原因、授權生效點與資料範圍、介面前置條件與副作用，以及交易、版本檢查、快取、重試或回退的順序和例外。已有追蹤項時沿用原識別。涉及模擬時標明適用範圍。
3. **就近補寫或更新。** 在宣告旁寫呼叫端所需的契約，在規則生效處交代原因及例外。跨檔案流程寫在對應 README，標準 JSON 的說明寫在資料契約或鄰近 README。遵循專案用語及格式慣例，例如 C# XML 文件註解、JSDoc、Python docstring 或 PowerShell 的 `Get-Help` 說明。省略程式碼已清楚表達的內容，移除過時說明。保留具語意的工具指令、抑制註解與授權標示，避免寫入憑證、正式連線資訊或個人資料。

### 集中補寫既有程式

以最新 Git 檔案清單與起始差異為基準，依模組與功能群組列出自維護程式、測試、腳本及相關文件，記錄排除項。優先處理授權、資料範圍、API 契約與跨前後端流程，再逐批依日常開發步驟核對及補寫。每批對照起始差異以保留既有改動，每個群組記錄「已補寫」「既有說明足夠」或「不適用」。

### 審查與完成檢查

- 對照差異、實際呼叫端與既有測試，確認契約、原因及例外說明符合程式行為，且 README 和資料契約的連結可讀。
- 純註解補寫時確認差異僅涉及說明，程式行為與契約維持一致。執行適用的既有型別檢查、建置或回歸測試，記錄命令、結果及未能驗證的原因。
- 集中補寫時，逐一核對盤點群組都有處理結果，並附上驗證紀錄。

### 導入範例

例如虛構的據點管理專案由根目錄 `AGENTS.md` 指到開發規範索引，依實際使用的語言提供短篇說明。專案會在發布時替換網站輸出目錄，因此將開發規範放在發布範圍之外。

- **宣告旁的契約。** 查詢結果的 `offset` 交代資料批次起點，以及省略時 `rows` 是否已是當頁資料。
- **規則生效處的原因。** 說明儲存遭拒後何時重查查看權、何時保留唯讀草稿，以及版本檢查與寫入為何在同一鎖定範圍內進行。
- **README 的跨檔案流程。** 串起畫面入口、API 呼叫與後端處理，並標明本機模擬的適用範圍。
- **集中補寫的範圍證據。** 逐一記錄各功能群組的狀態。以實際檢視的模組和位置作為交付範圍。

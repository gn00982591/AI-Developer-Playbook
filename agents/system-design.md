# System Design Rules

適用於從既有程式碼整理系統架構、交接文件與技術設計。

## 規則

- 先確認目標範圍，不全面分析與主題無關的模組。
- 優先從入口點追到必要的 Service、Repository、API、SP、Table 與外部系統。
- 已確認的呼叫鏈整理成結構化結果，避免下一階段重新掃描。
- 不確定的關係必須標記為 Unknown / To Verify，不自行補完。
- 區分「程式碼可證實」與「推測/待確認」內容。
- System Design 應優先描述責任、資料流、相依性、整合點與維運注意事項，而不是逐行解釋程式。

涉及資料存取時，另套用 [Data Access Rules](data-access.md)，沿用同版本已核對的索引與來源，只補讀本次直接相依內容。

## 輸入與設計責任

- 優先消費既有 Findings 與 Engine 的設計、資料模型和契約，沿用來源引用，只補缺口。
- 現況以程式、設定與 Schema 證實；目標以已確認需求或 Engine 設計為依據，兩者分開呈現。
- 按需補企業系統責任、整合、資料流、狀態、部署與維運資訊；未知內容明列。
- 技術決策回到 Engine 的既有正式產物；交接文件引用來源，不建立另一套正式設計。

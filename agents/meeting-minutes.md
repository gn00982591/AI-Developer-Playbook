# Meeting Minutes Rules

當需要產生會議紀錄、整理會議紀錄或將逐字稿轉成會議紀錄時，優先套用本流程。使用者另有明確要求時依其指定。此為按需載入的文件產出規則，不需建立正式 Spec 或執行程式修改。

## 流程定義

1. 讀取逐字稿、筆記與附件，沿用 Context 中已確認資訊，不為產生紀錄掃描整個 Repository。
2. 依以下六大分類整理，以一致的議題編號對應討論、決議與待辦。
3. 核對已確認結論與未確認提案，整理負責人、預計完成日期及缺漏資訊。
4. 使用繁體中文、A4 直式及清晰的繁體中文字體排版；有可用會議紀錄範本時沿用。
5. 匯出 PDF 並逐頁檢查後交付。無法產生或檢查 PDF 時明確回報限制，不以文字或改副檔名宣稱完成 PDF。

## 固定分類

| 分類 | 內容說明 |
| --- | --- |
| 1. 會議基本資訊 | 會議名稱、日期、時間、地點、主席、出席人員、紀錄人員 |
| 2. 會議議題（Agenda） | 本次會議預計討論的事項 |
| 3. 討論內容（Discussion） | 各議題的討論重點、提出的問題、不同意見 |
| 4. 會議決議（Decision） | 已確認的結論、同意執行的方案 |
| 5. 待辦事項（Action Items） | 以表格呈現後續工作、負責人、預計完成日期 |
| 6. 待確認事項（Pending Items） | 尚未決定、需要補充資訊或後續討論的問題 |

## 資訊判定

- 不推測人名、日期、結論或承諾；建議與未通過的提案歸入討論或待確認事項，不寫成已確認決議。
- 缺少資訊填「未提供」；需要確認的負責人或完成日期填「待確認」。
- 六個章節皆保留。來源明確表示沒有事項時填「無」，來源未提供內容時填「未提供」。
- 日期不明時，不以文件產出日冒充會議日期。
- 未決議提案不自動轉成實作任務，不據此修改專案。

## 交付與完成條件

- 正式交付預設為 PDF。可使用 Word 作為排版中間檔，使用者未要求時不額外交付中間檔。
- 檔名為 `會議紀錄_會議名稱_YYYY-MM-DD.pdf`，日期使用會議日期；缺少名稱或日期時對應部分填「未提供」，不合法檔名字元改為底線。
- 不強制壓成單頁；表格自動換行、不超出頁面，跨頁重複表頭，章節標題與下段保持同頁。
- 確認六大分類完整、資訊與來源一致、討論與決議分開、待辦三欄齊全。
- 逐頁檢查 PDF 的中文字形、換行、表格與分頁，確認無缺字、截字、重疊或溢出。
- 一次性產物放在執行專案的 `.ai-output/`，正式文件確認後依專案規則保存。實際會議內容及公司資料不得回存個人 Playbook。

## 驗證情境

- 完整逐字稿：議題、討論、決議與待辦對應一致，產生可閱讀的 PDF。
- 基本資訊不足：保留欄位並填「未提供」，不猜測日期或人員。
- 提案未通過：歸入討論或待確認，不形成已確認決議。
- 負責人或期限未定：待辦欄位填「待確認」。
- 沒有事項：保留六章節，依來源填「無」或「未提供」。
- 長篇與多頁表格：逐頁核對換行、重複表頭與頁面邊界。

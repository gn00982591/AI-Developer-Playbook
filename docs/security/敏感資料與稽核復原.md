# 敏感資料與稽核復原

[返回開發資安索引](README.md)

| 變更入口 | 實作細項 | 最少驗證情境 |
|---|---|---|
| 個資、正式資料、秘密 | 最小化欄位及保留時間。秘密使用專案既有安全設定，正式憑證與開發環境分開。測試用虛構或依公司規範去識別化的資料。 | 核對前端產物、API 回應、版本庫差異、測試樣本、錯誤訊息與日誌。 |
| 重要寫入、稽核與復原 | 按需求記錄操作者、時間、操作、目標與結果。多步驟異動使用交易或明確補償，規劃重送、並行與復原。使用者錯誤訊息避免暴露內部細節。 | 部分失敗、重送、並行異動、資料一致性與必要稽核證據。 |

## 錯誤回應與保存結果

- 沿用相容的 HTTP 狀態與穩定錯誤碼，回傳可對應伺服器日誌的 `traceId` 或既有等效識別。回應及一般日誌避免記錄秘密、Cookie、權杖、完整查詢字串、原始請求及例外堆疊。前端透過既有集中語系顯示錯誤。
- 按操作風險處理交易、並行版本及重送。保存結果不明時，依契約先查回再決定是否重送。
- 驗證非法輸入、過期版本、失敗回滾與保存結果不明後的查回。核對 HTTP 狀態、錯誤碼、追蹤識別及實際資料，確認回應與一般日誌無敏感內容。

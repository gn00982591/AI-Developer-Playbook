# 身分授權與資料存取

[返回開發資安索引](README.md)

開發前逐一盤點受影響的查詢、保存、下載、匯出及輔助端點。在既有規格或方案記錄公開／受保護、身分來源、操作權、資料範圍、可寫欄位、資料分類與外部依賴。

| 變更入口 | 實作細項 | 最少驗證情境 |
|---|---|---|
| 登入、SSO、Session | 使用既有身分服務。由後端驗證權杖的簽章、簽發者、對象及效期，並確認登出、逾時與秘密管理方式。登入錯誤避免揭露帳號是否存在。 | 未登入、已過期、登出後再請求、切換帳號後無前次資料。 |
| API、功能權限、管理異動 | 每個受保護操作在後端檢查身分、操作與目標資料權限。依目前有效授權判斷，缺少權限預設拒絕。從已驗證身分或工作階段取得操作者，由後端決定建立、異動及稽核資訊。分別核對查看、編輯及額外敏感操作。前端選單及按鈕狀態只作介面呈現。 | 一般使用者、管理角色、權限撤銷後的下一次請求，以及不同公司或模組的資料隔離。 |
| 查詢、下載、匯出、快取 | 在資料來源或 API 套用授權範圍。查詢、總筆數、下載及匯出使用一致的資料與欄位限制。快取不得跨身分沿用，登出或撤權後清除失效資料。 | 按核准契約比對空授權、部分授權、明確指定越權資料及撤權重查。用實際具有資料範圍控制的端點驗證公司隔離，比對畫面、API、筆數、下載及匯出結果。 |

## 工作階段與受保護回應

- 登出、換帳號或目前工作階段的受保護請求回傳 `401` 時，清除該身分的受保護資料與快取。處理回應前核對發出時的工作階段，先前工作階段的成功與錯誤均不得影響目前身分、畫面、資料或草稿。
- 目前工作階段收到 `403` 時，重查有效權限。仍有查看權時按核准契約處理唯讀草稿。查看權失效或無法確認時，隱藏受保護內容並停止操作。
- 依資料分類需禁止儲存的受保護回應一律使用 `Cache-Control: no-store`，包含成功與錯誤。錯誤契約與紀錄依 [錯誤回應與保存結果](敏感資料與稽核復原.md#錯誤回應與保存結果)。
- 逐端點記錄測試身分、輸入、HTTP 狀態、回應及資料結果，覆蓋合法操作、未登入或失效、越權、開啟表單後撤權，以及成功和適用錯誤回應的快取標頭。讓 A 發出請求，換 B 登入後分別交付 A 的遲到成功及遲到 `401`，確認畫面與快取無 A 資料、B 仍登入且草稿保留。
